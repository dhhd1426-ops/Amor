# 人物志 · 小说角色工作台（v13.1）

放入一部 6 MB 以内的 TXT / Markdown 小说，自动生成带原文出处的角色卡：身份、形貌、性情、背景、剧情称呼、人际态度与对白，可导出为酒馆（SillyTavern）角色卡。网页与安卓 App 共用同一份页面。

## 目录

| 路径 | 内容 |

| `src/style.css` | 全部样式，含深色模式、手机适配、导入框变形的进度圈 |

| `src/cards.js` | 酒馆角色卡导出：PNG（内嵌 ccv3 + chara）、JSON、整书 zip、Markdown |
| `src/providers.js` | 9 家模型接口；按供应商设输出上限、JSON 模式、截断识别 |
| `src/engine.js` | 原版本地提取引擎（人名识别、称呼归并、字段线索），未改动 |

| `dist/` | 可直接部署的静态站点（`index.html` 由构建生成，另含殷洛妍样卡） |

## 构建

```bash
python3 build.py                                   # 生成 dist/index.html 与 prototype/index.html
KS=~/keys/renwuzhi.jks KS_PASS=*** ./build-apk.sh  # 生成 out/renwuzhi-v<版本>.apk
```

APK 构建只需 Java 17+ 与 Python 3；脚本会从 GitHub Releases 下载 Apktool 2.12.1 与 uber-apk-signer 1.3.0。目标 Android 15（API 35），最低 Android 7.0（API 24）。升级版本时修改 `android/apktool.yml` 的 `versionCode` 与 `versionName`。

签名密钥不入库。以后发布的新版必须用同一个密钥签名，才能覆盖安装、保留数据。

## 分析机制

1. **本地预处理**：识别章节、人名与称呼，按“人称 / 尊称 / 昵称 / 外号”等说法抽出剧情称呼标签。不调用模型，5.6 MB 约 1.5 秒。
2. **按章节分段**：在章节边界切开；短章合并到 6000 字以上，单段不超过 1.2 万字。
3. **逐段请求**：每段带行号原文，附上本段出现的人物、已知称呼和缺失字段；默认 3 段并发，可设 1～8。
4. **容错**：
   - 限流、5xx、超时、空内容：自动退避重试 3 次。
   - 输出被截断或 JSON 不完整：把这一段对半拆开重新请求，最多拆 3 层。
   - 供应商不支持 JSON 模式：自动退回普通模式。
5. **逐字核对**：模型给出的每条证据必须在对应行原文中逐字找到，否则丢弃。
6. **合并**：按本名与严格称呼合并人物，态度和对白按行号排序，剧情称呼归到对应人物名下。
7. **断点与缓存**：每段完成即存入 IndexedDB，停止后可续跑；整本完成后缓存结果，同一本书再导入时直接恢复。

## 测试

```bash
pip install playwright && python3 tests/e2e_deepseek.py [小说.txt] [视口宽度]
```

模拟接口按 DeepSeek 的规则校验请求（输出上限 ≤ 8192、JSON 模式要求提示里含“json”），并随机返回限流、5xx、空内容、代码块包裹和输出截断。用 1 MB 样本实测：82 次截断全部拆段完成，11 次限流、6 次 5xx、3 次空内容全部自动重试，停止 0.1 秒生效，续跑与缓存恢复均正常。

## 运行环境说明

- **安卓 App**：页面从包内本地文件加载，并开启本地页面跨域访问，可直连各家模型接口，不受浏览器跨域限制。
- **网页版**：能否直连取决于供应商是否允许浏览器跨域请求。在 claude.ai 预览中，外部请求会被沙盒拦截，此时可选“演示模型”体验流程。
