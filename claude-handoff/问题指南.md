# 问题指南（给之后接手的 Claude）

动手前先读完这份。每一条都是真出过的问题：现象 → 根因 → 以后怎么做。
每次会话结束前，把新遇到的问题按同样格式加进来。项目文档里也有一份给用户看的同名指南，两份一起更新。

## 一、做事规矩（用户定的，不能跳）

1. **页面、动效改动先做网页原型**，发出来给用户试，等用户说可以才改 App 代码。纯删按钮这类没有新交互的小改动可以直接做。
2. **用户点头后才提交**，推到 `check` 分支编译。
3. **编译通过后发安装包直链**：链接要能在浏览器里点开直接下载（Release 的 asset 地址），不要只给构建记录。做法见第五节。
4. **少编译**：先把代码自查一遍再推。编译中途用户又提了小需求，等这次结果出来后合在一起提交，只发一个包。
5. **界面不加多余的小字说明**，让布局本身说清楚。
6. **每个新功能都带诊断框**（用户定的，第 549 版起）：出问题时在 App 里能看到一个等宽字、能选中、带「复制」的框，写全哪一步坏了、完整报错（不截断）、手机型号、显卡、App 版本。用户截图或复制发来就能定位，不用来回问。现成的组件是 `Wallpaper.kt` 的 `DiagBox(text)`，直接用。
7. **用现成、成熟的做法**：先看 Kelivo 源码（`Chevey339/kelivo`）、主流开源库怎么做，不要自己发明。动效参数照 `dhhd1426-ops/dongxiaosheji` 的 `MOTION_GUIDE.md`。
8. **回复用中文**。

## 三、界面（Compose）

### 底部弹层
- **问题**：弹层四角露出方形黑边，左右和底部碰不到屏幕边。
- **根因**：`KSheetHost` 画在页面内容区里，遮罩只盖内容区那一块方框。
- **规矩**：
  - 页面里的 `KSheetHost(sheet)` 只负责登记，真正画在 `MainActivity` 根上的 `SheetLayerHost()`：遮罩铺满整屏，弹层贴边，最高 90% 屏高，返回手势先关弹层。
  - 任何地方临时要弹一层（选单、删除确认、添加供应商），用全 App 共用的 `AppSheet.open { }`，它总在最上面。
  - 内容自带滚动时用 `sheet.openBare { }`。外面再套一层 `verticalScroll` 会崩。

### 键盘
- App 开了 edge-to-edge，清单里的 `adjustResize` 不起作用，所以要自己处理键盘：
  - 弹层：外面包 `imePadding()`，跟着键盘动画逐帧走。
  - 关弹层：只在「开着 → 关上」那一下 `clearFocus` 并 `keyboard.hide()`，让键盘和弹层一起退场。不能在第一次组合时就清焦点，否则页面一打开就抢走别处的焦点。
- **问题**：新对话的问候在键盘弹起、输入框变两行后，被压在输入框下面。
  - **根因**：问候单独一层，上下边距按「键盘收起、输入框一行」写死。
  - **规矩**：要在剩余空间里居中的东西，放进本来就跟着键盘变化的区域（`Chat.kt` 里带 `imePadding` 那一列的 `weight(1f)` 区），不要另起一层自己算边距。空间太矮时用 `BoxWithConstraints` 按剩余高度缩小次要元素（如 `ChatHello` 里的 Vignette 标志）。
- 改了任何带输入框的页面，都要想一遍「键盘弹起 / 收回时这里会怎样」。

### 从聊天里打开的页面，返回要回聊天（第 546 版起）
- **问题**：点聊天里的世界书卡进了世界书页，按返回却退到「我的」，不回聊天。
  - **原因**：「我的」卡片里的页面返回是写死的上一级（世界书 → mine），不管是从哪儿进来的。
  - **规矩**：从卡片外面（聊天）打开「我的」里的某一页，一律用 `mineNav.go(screen)`，它记下入口 `entry`；在入口那页按返回（返回手势走 `back()`，左上角走 `nav.up(上一级)`）就收起卡片回聊天。新加页面的左上角返回不要再写 `nav.screen = "上一级"`，用 `nav.up("上一级")` 或 `nav.back()`。
  - 平常点「我的」打开要清掉入口（`onMine` 里 `entry = ""`），卡片关上时也清（`onClosed`）。

### 同一功能只做一套界面、一个入口
- **问题**：助理设置里选模型是一长串平铺，和聊天里那套按供应商分页的不一样；世界书在输入框旁和「＋」菜单里各有一个入口。
- **规矩**：
  - 选模型全 App 只用 `ModelPicker.kt` 的 `ModelPages`。场景差异靠参数：`sel` 定哪个打勾（null 表示跟随全局），`header` 加第一页顶上一行，`onAdd` 加「添加供应商」。
  - 加按钮、加入口前，先在代码里搜有没有现成的。世界书入口只在「＋」菜单（`ChatTools.kt`）。

### 名单不要写死
- 供应商 = `BUILTIN_PROVIDERS` + `CUSTOM_PROVIDERS`，`PROVIDERS` 是两者合起来的 getter。用户自建的存在 `assistant-config` 的 `custom` 里，用 `store.addProvider(...)` 添加、`store.removeProvider(id)` 删除。删除时会把用到它的全局模型和助理默认模型一起退回（`AssistantExt.dropProvider`）。
- 以后有类似的名单（语音服务、搜索源等）也照这个做：内置加自建，删除时清理所有引用。

### 拖动排序
- 用 `sh.calvin.reorderable:reorderable:3.1.0`，不要手写。
  - `LazyColumn`：`rememberReorderableLazyListState(listState) { from, to -> … }`、`ReorderableItem(state, key) { dragging -> }`，把手用 `Modifier.draggableHandle()` 或 `longPressDraggableHandle()`。
  - 普通 `Column`：`ReorderableColumn(list, onSettle = { from, to -> }, onMove = { 震动 }) { i, item, dragging -> key(item.id) { ReorderableItem { … } } }`。
- 例子：`WorldBookUi.kt`，长按书名拖书，拖条目左边的把手排条目。

### 编译坑
- **问题**：`ColumnScope.AnimatedVisibility … cannot be called in this context with an implicit receiver`。
  - **原因**：在 `ColumnScope.xxx()` 函数里的 `Box` 中写了 `AnimatedVisibility`。
  - **改法**：拆成独立的 `@Composable` 函数（例：`WorldBookUi.kt` 的 `WbToast`）。
- `HapticFeedbackType` 可以用 `SegmentFrequentTick`、`GestureThresholdActivate`、`LongPress`、`TextHandleMove`（Compose 1.12）。
- **问题**（第 551 版第一次编译）：`Unresolved reference 'detectVerticalDragGestures'`。**原因**：手势检测是 `PointerInputScope` 的扩展函数，写成 `androidx.compose.foundation.gestures.detectVerticalDragGestures(…)` 带包名调用找不到。**改法**：顶部 `import` 后直接调用。本地 kotlinc 没有 Compose 库，这类错看不出来，凡是带包名调用的 Compose 函数都改成 import。
- 项目没有 material3 依赖，滑条、开关自己画（例：`Wallpaper.kt` 的 `TuneSlider`），不为一个控件加库。
- 新加依赖前先确认版本存在、兼容 Kotlin 2.3、compileSdk 37、minSdk 29。仓库在 mavenCentral。

### 用量页（第 536 版起）
- 结构只有两张卡：当前渠道余额卡 + Token 统计卡。不要再加「当前会话」「每周限额」「所有模型」这类卡，用户明确说冗余。
- 余额卡跟着当前模型的渠道走；点头部弹层看各家余额，手动选了别家，换模型时回到当前渠道。
- 满格 = 最近一次充值后的余额（余额比上次多就算充值），存在 `usage-topup-v1`；OpenRouter 用 `/api/v1/credits` 的总额。
- 花费只按 `ModelUsage.PRICES` 里核实过的官方价算；没单价的模型只显示 Token，不要猜价。
- DeepSeek 充值（`DeepSeekPay.kt`）：官方没有公开下单接口，连官方客户端 DeepSeek Harness 也是内嵌 `/top_up`。做法是在 1dp 高、全透明的已登录 WebView 里自动填金额、选付款方式、点提交，拦截 `weixin://`、`alipays://`、`intent://` 拉起付款 App；15 秒没拉起就展开页面手动完成。登录页里的「微信授权登录」也会跳 `weixin://`，那时不能当成付款关弹层。
- 页面结构变了导致自动填写失败时，先让用户截充值页的图，再改 `DeepSeekPay.script()` 的匹配规则。

### 分层、圆角、描边（第 558 版起，照 FlClash，见项目文档《设计参考-FlClash》）
- **圆角**：全 App 用连续曲率。`Corners.kt` 里有同名的 `RoundedCornerShape(...)`（Dp / 百分比 / 四角），形状来自 `com.kyant.shapes`（Kyant0/Shapes，Apache-2.0，源码随附，去掉了 ui-util 依赖）。**新文件不要 `import androidx.compose.foundation.shape.RoundedCornerShape`**，否则会盖过它，变回普通圆角。返回类型是 `Shape`，不要把变量写成 `: RoundedCornerShape`。`CircleShape` 只用于正方形的东西。
- **不描边**：卡片、气泡、按钮靠「比底下亮一档」分层，`Skin.workLine`、`Page.glassBorder` 都是透明的。只有状态才描边（正在编辑、出错、选中的色块或壁纸外圈）。
- **层级**：暗黑主题页 `#161413` → 卡 `#292726` → 块和弹出 `#353332`，只往亮走；白色主题是灰页 `#F1EFEB`、白卡 `#FCFBF9`、灰块 `#ECEAE5`。新卡片取 `Skin.card` / `workFill`，卡里的块取 `Skin.tint`，不要自己写色值。
- **分割线** = `Page.line`（字色 14%）。
- **选中**：只打勾，不铺暖色底。分段控件选中的那格用实心 `Skin.accent`，字用 `Skin.onAccent`。
- 实心胶囊按钮用 `LiquidPill`（侧栏「新对话」）：反色实心 + 高光 + 上沿亮边 + 阴影，按下放大 1.06 + 手指下亮光。用户比较过「按下变亮不缩放」，选的是放大。
- 改配色时用户的判断标准是「一眼能认出是按钮」。磨砂、深色玻璃那种把按钮做「融进去」的方案被否了。

## 四、网页原型

- 图表配色先跑 dataviz 的 `validate_palette.js`（深色底 `#2b3038`）：统计卡的输入 / 缓存 / 输出用 `#3FA35E` / `#6F83EA` / `#CF763A`，已通过。

- **键盘**：viewport 加 `interactive-widget=resizes-content`；iOS 用 `visualViewport` 算键盘高度，把弹层抬起来，收起后 `scrollTo(0,0)`；输入框字号至少 16px，否则 iOS 聚焦时会放大页面、不再缩回。
- **问题**：用 JS 设高度的块高度为 0。
  - **原因**：父元素高度随内容（auto），子元素写了 `flex:1`，flex-basis 0 盖掉了设的 `height`。
  - **改法**：这类块写 `flex:none`。
- **弹层**：遮罩铺满整屏、弹层贴边、可下拖关闭，进 420ms `decel`、出 280ms `accel`（dongxiaosheji `amor-bottom-sheet`）。
- **问题**：原型在 Claude App 里打开时，键盘弹起把弹层里的输入框挡住。
  - **原因**：页面嵌在 App 里，键盘盖上来时 `visualViewport` 和 `innerHeight` 都不变，量不到键盘。
  - **改法**：输入框获得焦点约 380ms 后，如果高度没变，就把整个弹层贴到屏幕顶上（`.sheet.lift{top:12px;bottom:auto}`）。贴顶的弹层关闭时 `translateY(105%)` 不够，要用 `translateY(100vh)`，否则会留半截在屏幕上。
- **问题**：从宽度 0 展开的输入框，展开过程中输入，字会倒着排。
  - **改法**：从按钮原来的宽度开始展开，不要从 0 开始。
- **发布前**用 Playwright 截图自查一遍（`python3` 已装 playwright），发布时用 `publish_files`。
- 需要对比方案时，在原型里放一个切换开关（例：聊天模型原型的 A / B）。

## 五、发安装包

- `check` 分支编译只出 artifact，不出 Release。直链这样发：
  1. 编号 = 526 + 那次 "Android APK" run 的 `run_number`（例：run 9 → 第 535 版）。
  2. 查 artifact：`gh api repos/dhhd1426-ops/Amor/actions/runs/<run id>/artifacts`，记下 `id` 和 `digest`（sha256）。
  3. 从编译通过的那个提交开分支 `release/check-apk-<编号>`，加 `.github/workflows/publish-check-apk-<编号>.yml`（照 `release/check-apk-535` 分支里那份改编号、artifact id、sha256、目标提交、说明）。推上去，它会下载 artifact、核对 sha256、`gh release create app-build-<编号>`。
  4. 直链：`https://github.com/dhhd1426-ops/Amor/releases/download/app-build-<编号>/fuguang-lueying-<编号>.apk`
- 这边下载不了 artifact（blob 地址被拦），所以校验用 API 返回的 `digest`。
- `gh` 不能用 GraphQL（`gh release list` 之类会 403），一律用 `gh api repos/...`。
- 编译失败：用 `gh api repos/dhhd1426-ops/Amor/check-runs/<job id>/annotations` 读错误行。

### 壁纸（第 548 版起）
- 「我的 → 壁纸」：导入 Wallpaper Engine 手机版导出的 `.mpkg` 场景壁纸、图片、视频。原型 `KNLw65Bt1Q93XKLzgu4JfF`。动手前读项目文档《壁纸-mpkg格式》《壁纸-渲染器笔记》《壁纸-云朵天气的经验》。
- 代码：`WePack.kt`（解包、解贴图）、`WeScene.kt`（渲染器）、`WeRun.kt`（渲染线程、脚本、频谱）、`Wallpaper.kt`（`Walls` 存储、背景层 `WallBackdrop`、壁纸页）。
- **渲染器是照原型里的 `we.js` 一一对应搬的。** 要改效果、补新功能（粒子、骨骼、新贴图格式），先改 `we.js`，在这边用 Playwright 截图对着包里的 `preview.jpg` 看对了，再同步到 `WeScene.kt`。不要直接在 Kotlin 里试，那样只能靠 CI 一轮轮编。
- 不移植别人的引擎（云朵天气移植过 Vulkan 那套，做完一个版本就删了）。用 `TextureView` 不用 `SurfaceView`：聊天时背景要虚化、磨砂卡片要透出它，这两样只对画进界面层的内容起作用。
- 文字层的脚本（时钟、日期）在一个不挂到界面、断网、不许读文件的 `WebView` 里跑（`WeScripts`），没有加 QuickJS 这类原生库：少一个依赖，创意工坊的脚本也关在沙盒进程里。
- 定下的规矩：
  - 壁纸只在透明磨砂主题下显示；选了壁纸自动换回透明磨砂。
  - 构图（缩放、左右上下）只在壁纸页能动：空白处单指拖、双指捏合，点已选中的那张只看壁纸。「我的」、聊天页不能拖。
  - 频谱跟手机里正在播放的声音（`Visualizer(0)`，要录音权限，进壁纸页时问一次）。
  - `Walls.clear`（正在壁纸页）为真时：背景不虚化、`CenterCardLayer` 的底色和磨砂让开、聊天页淡掉但**不拆**（`pageIn(chatAlpha * wallAway)`）、助理的聊天背景不画。以后别的页面要「看清背景」也用这个开关，不要另做。
- 还没做：粒子、骨骼动画、DXT 贴图、图层的特殊混合模式、只算看得见的那一块、帧率设置（现在固定每秒 30 帧）。用户有用到的壁纸时让他把 `.mpkg` 发来再补。
- **这边能本地检查不带 Compose 的 Kotlin 文件了**（第 548 版一次编过就是靠它）：
  - 编译器：`curl -L -o kotlinc.zip https://github.com/JetBrains/kotlin/releases/download/v2.3.0/kotlin-compiler-2.3.0.zip`
  - `android.jar`：`git clone --depth 1 --filter=blob:none --sparse https://github.com/Sable/android-platforms ap && git -C ap sparse-checkout set android-34`（直接下载会被拦，只有 git 走得通）
  - 检查：`JAVA_TOOL_OPTIONS= kotlinc/bin/kotlinc -cp ap/android-34/android.jar -d out 文件…`。不碰安卓类的逻辑（解包、解贴图）还能在 JVM 上对着真文件跑一遍。
  - 带 Compose 的文件拿不到库，只能看出语法错误：把报错里「unresolved」之类的滤掉，剩下 `syntax error` 就是真的。
- 原型踩的坑：
  - **问题**：用户在原型里双指捏合，整个页面被放大（按钮变得很大）。**原因**：没禁页面缩放。**改法**：viewport 加 `maximum-scale=1,user-scalable=no`，页面 `touch-action:none`，只让要滚的那一块自己当滚动容器并写 `touch-action:pan-y`（写在父级上会连子级一起禁掉）。
  - **问题**：原型脚本整段不执行，点了没反应、控制台也没报错。**原因**：顶层写了 `let top`，和 `window.top` 重名。**规矩**：顶层变量不要叫 `top`、`name`、`status`、`parent` 这类 window 自带的名字。
  - **问题**：用 Python 脚本批量替换代码时，把 `var kind = ""` 写在双引号字符串里，两个引号被吃掉，变成 `var kind = ;`。**规矩**：替换的内容里有引号就用三引号，改完跑一遍上面的语法检查。
- **问题**（第 548 版）：用户导入的三张创意工坊壁纸大部分图层没画出来。**原因**：① 缺引擎自带的 `common_perspective.h`、`common_blur.h`（Balloon 没用到，所以原型里没发现）；② 着色器用了 HLSL 写法 `float x = texSample2D(...)`；③ 一个效果编译失败就整层跳过。**改法**：两个头文件和 HLSL 修正从云朵天气搬过来（`git show 6af1250^:app/www/we/shaders/…`、`wall.js` 的 `translate`）；效果失败只跳过这个效果。**教训**：只拿一张壁纸验证不够，云朵天气踩过的坑要整份对照着搬，不要只挑这张用到的。
- **第 549 版起照官方源码**：官方安卓版安装包里 `assets/` 是全套引擎素材源码（130 个着色器、12 个公共头文件、201 张基础贴图、9 张示例壁纸）。App 运行时读用户手机上已装的官方 App（`WeEngine`，清单里 `<queries>` 声明了包名），不打包。开发时的拿法和批量测试台见 `tools/wallpaper-bench/README.md`；清单见项目文档《壁纸-官方安卓版素材》。
  - **逆向官方引擎**：素材以外的行为（粒子默认值、3D 模型 / 骨骼格式、属性脚本 API）都在原生库 `libscenejni.so` 里，**符号没去掉**，能按 C++ 名字查。做 3D 模型、骨骼、子粒子、属性脚本之前先读 `tools/wallpaper-bench/逆向.md`，用 `re.sh` 查官方怎么做，不要猜。粒子组件的官方默认值在 `ParticleCommands::*Defaults` 函数里，之前猜的默认值要照它核对。
  - 不要把官方素材提交到任何仓库（公开、私有都不要）：系统的安全检查会拦，也确实不该。只在工作区里用。
  - 贴图格式编号以官方 `common_fragment.h` 为准：0 RGBA8888 1 RGB888 2 RGB565 3 ETC1 4 DXT5 5 ETC2_RGBA8 6 DXT3 7 DXT1 8 RG88 9 R8 10 RG1616F 11 R16F 12 BC7。
  - 图层 = 模型 + 材质：材质自己定着色器、贴图、参数、混合方式；大小先看图层 `size`，再看模型的 `width`/`height`（手机版导出的贴图常被压到一半），最后才是贴图。场景文件名读 `project.json` 的 `file`。
- **问题**：照官方源码后，所有壁纸都报 `BONECOUNT undeclared`。**原因**：「`#if` 里没定义的名字全局 `#define 0`」把 `SKINNING_ALPHA` 也定义了，而官方同一个名字还用在 `#ifdef` 里。**改法**：只在 `#if`/`#elif` 那一行里把未定义的名字换成 0。
- **问题**：测试台上 Balloon 只剩几片头发。**原因**：并行上传贴图时，在「绑定贴图」和「解码完成」之间有 `await`，别的贴图抢先绑定，图传进了别人的贴图里。**规矩**：GL 的绑定和上传之间不能有 `await`，先解码完再绑定。
- **Kotlin 坑**：`Regex.replace(input) { … }` 的返回值是**原样插入**的，不要再套 `Matcher.quoteReplacement`，否则官方头文件里宏定义续行的反斜杠会变成两个。
- **第 551 版**：粒子（CPU 模拟 + 官方 `genericparticle` 着色器）、用户属性（`project.json` 的 `general.properties`）、壁纸设置面板（只看壁纸时底部把手：覆盖 / 填充 / 自由、翻转、速度、背景色、重置，取景存在 `Wall.view` 的 9 个数里，场景、图片、视频同一套规则）。
  - **问题**：粒子一个都不显示。**原因**：作者着色器写 `uniform lowp vec3 …`，读参数注释的正则没想到精度修饰词。**改法**：正则允许 `lowp|mediump|highp`。
  - **问题**：粒子颜色偏黄。**原因**：`colorrandom` 没写 min/max 时默认是 0–255 全随机，当成白色了。
  - 用户属性两种写法：`{"user":"名字","value":…}` 取属性当前值；`{"user":{"name","condition"}}` 是布尔条件（图层显示与否）。材质 `usershadervalues` 是「参数名 → 属性名」。
  - **规矩**：JS 里把说明写在同一行代码后面时，别用 `//` 把后半行代码吞掉；改完 `node --check`。
  - 还没做：3D 模型（4 张官方示例要）、属性脚本（razer_vortex、dino_run）、骨骼、子粒子、精灵图动画。用户有张「人物后面背景是黑的」壁纸在等他发 `.mpkg` 和诊断框。
- **第 553 版起场景壁纸走官方引擎**（用户定的：自己用，照官方）：`WeOfficial.kt`。借官方 App 的类加载器（`createPackageContext(…, CONTEXT_INCLUDE_CODE|CONTEXT_IGNORE_SECURITY)`）装 `io.wallpaperengine.wrapper.SceneLib`，反射调它自己的方法，顺序照官方 `SceneWallpaperView`：`initLibrary(Context)` → `initContext(Context):Int` → `initScene(id, 路径)` → `resizeScene(id,w,h)`（**顺序不能反**：`Main` 在 `initScene` 里才建，`resizeScene` 直接用它，第 553 版先 resize 空指针崩了） → 每帧 `updateScene(id)`；`getSceneCanvasSize(id, PointF)` 为真算载完；收尾 `shutdownScene`、`destroyContext`。全部接口写法见第 552 版探测结果（长按场景壁纸 →「官方引擎」能再看）。
  - 官方库在安装包里不压缩（`extractNativeLibs=false`），只能用官方的类加载器加载（`findLibrary` 返回 `base.apk!/lib/arm64-v8a/libscenejni.so`），不要自己 `System.load`。
  - 给引擎的 Context（`OfficialCtx`）：素材、资源、类加载器用官方的，文件目录、系统服务、权限用 Amor 的。
  - 原生崩溃抓不住，靠记号（第 555 版自检后定的）：目录 `we-official-run/<壁纸 id>`，**官方引擎在画的时候一直留着**，切后台（`playing=false`）、换壁纸、线程收尾才擦；App 启动后只查一次，留着记号的那张以后用自带渲染器，诊断框写停在哪；长按「官方引擎」重试并当场重载（`Walls.epoch++`）。
    - **问题**（第 554 版）：画出第一帧就擦记号，画到一半才崩的壁纸会每次打开都崩；每次建表面都查记号，A 载入中切到 B 会把 A 冤枉成崩过；表面没了（折叠屏开合）跳出循环时没擦记号。**规矩**：「正在做危险的事」的记号，生命周期要盖住整件事；「上次崩没崩」只在进程启动时判一次；每个对象各记各的。
  - 取景：官方引擎不认 `Wall.view`。`SceneFrame`（`Wallpaper.kt`）让它按壁纸原比例画整张（表面 = 整张壁纸盖住屏幕的大小，只防离谱：最宽 8192 像素），外面用 `graphicsLayer` 缩放、挪位、转、翻，规则同 `Framed`。自带渲染器时 `SceneFrame` 是恒等的。两种情况必须是同一棵界面树，否则 TextureView 重建、引擎重载。
  - 这边的安全检查不让反编译官方 App 的 Java 代码（jadx 被拦），接口写法改由测试包在手机上反射读出来。不要再试反编译。
  - 第 557 版接上的三样（接口写法都是从 `libscenejni.so` 反汇编核对过的，不是猜的）：
    - 速度：`applySceneProperties(id, "{\"rate\":{\"value\":150}}")`，值是百分数，引擎自己除以 100。
    - 频谱：`sendAudioData(id, float[64])`，0–1；引擎自己复制成左右声道、合成 32 和 16 段。要不要听声音看 `project.json` 的 `general.supportsaudioprocessing`。没声音时补一次全 0。
    - 触摸：`sendTouchInput(id, 按着没有, x, y)`，x y 是表面上的像素（引擎自己除以表面大小）。手指从 App 根上只看不拦地喂（`Walls.touch`，`App.kt` 根上的 `pointerInput`），经 `WeHost.touch` 按 `SceneFrame` 的取景反算到画面上。
    - `initScene` 里引擎自己读 `project.json` 的默认属性并应用，不用我们再喂一遍默认值。
  - 还没接：重力视差（`sendGravityInput`）、壁纸自带的设置项界面（`getSceneProperties` / `applySceneProperties`）。
  - **举一反三（第 554–556 版连着两次栽在同一类事上）**：
    - **问题一**：超宽壁纸（5120×1440）人物不见了。**原因**：只拿 16:9 的壁纸想过取景，把「怎么裁」交给了官方引擎的默认行为，超宽的被裁到人物在画面外。
    - **问题二**：修的时候为了省内存把表面限在两屏宽，画面先缩后放，用户一眼看出糊。**原因**：加限制时只算了内存，没算清晰度。
    - **规矩**：
      1. 凡是碰取景、表面大小、缩放的改动，动手前把这张表过一遍：壁纸比例（16:9、超宽 32:9、竖的 9:16、方的）× 屏幕形状（折叠屏展开近方形、合上细长、横过来）。每一格心算出表面多大、默认取景下缩放是多少。
      2. **默认取景下，表面一个像素 = 屏幕一个像素**。任何让它小于 1 的限制都是在降画质，要有非加不可的理由，并且在回复里明说代价。
      3. 「谁来决定这件事」换了人（引擎 → 我们，或反过来），就要把所有比例重新过一遍，不能只看眼前这张。
      4. 用户发截图说「不对」时，先问清是哪一版的截图，再下结论。
- 没有真机验证过：这边只在无显卡的浏览器里对过画面。真机上的流畅度、发热、个别显卡的着色器编译问题，要等用户反馈；出错的图层会被跳过，长按那张壁纸能看到跳过了哪些。
