# 问题指南（给之后接手的 Claude）

动手前先读完这份。每一条都是真出过的问题：现象 → 根因 → 以后怎么做。
每次会话结束前，把新遇到的问题按同样格式加进来。项目文档里也有一份给用户看的同名指南，两份一起更新。

## 一、做事规矩（用户定的，不能跳）

1. **页面、动效改动先做网页原型**，发出来给用户试，等用户说可以才改 App 代码。纯删按钮这类没有新交互的小改动可以直接做。
2. **用户点头后才提交**，推到 `check` 分支编译。
3. **编译通过后发安装包直链**：链接要能在浏览器里点开直接下载（Release 的 asset 地址），不要只给构建记录。做法见第五节。
4. **少编译**：先把代码自查一遍再推。编译中途用户又提了小需求，等这次结果出来后合在一起提交，只发一个包。
5. **界面不加多余的小字说明**，让布局本身说清楚。
6. **用现成、成熟的做法**：先看 Kelivo 源码（`Chevey339/kelivo`）、主流开源库怎么做，不要自己发明。动效参数照 `dhhd1426-ops/dongxiaosheji` 的 `MOTION_GUIDE.md`。
7. **回复用中文**。

## 三、界面（Compose）

### 底部弹层
- **问题**：弹层四角露出方形黑边，左右和底部碰不到屏幕边。
- **根因**：`KSheetHost` 画在页面内容区里，遮罩只盖内容区那一块方框。
- **规矩**：
  - 页面里的 `KSheetHost(sheet)` 只负责登记，真正画在 `MainActivity` 根上的 `SheetLayerHost()`：遮罩铺满整屏，弹层贴边，最高 90% 屏高，返回手势先关弹层。
  - 任何地方临时要弹一层（选单、删除确认、添加供应商），用全 App 共用的 `AppSheet.open { }`，它总在最上面。
  - 内容自带滚动时用 `sheet.openBare { }`。外面再套一层 `verticalScroll` 会崩。

### 键盘
- App 开了 edge-to-edge，清单里的 `adjustResize` 不起作用，所以要自己处理键盘：
  - 弹层：外面包 `imePadding()`，跟着键盘动画逐帧走。
  - 关弹层：只在「开着 → 关上」那一下 `clearFocus` 并 `keyboard.hide()`，让键盘和弹层一起退场。不能在第一次组合时就清焦点，否则页面一打开就抢走别处的焦点。
- **问题**：新对话的问候在键盘弹起、输入框变两行后，被压在输入框下面。
  - **根因**：问候单独一层，上下边距按「键盘收起、输入框一行」写死。
  - **规矩**：要在剩余空间里居中的东西，放进本来就跟着键盘变化的区域（`Chat.kt` 里带 `imePadding` 那一列的 `weight(1f)` 区），不要另起一层自己算边距。空间太矮时用 `BoxWithConstraints` 按剩余高度缩小次要元素（如 `ChatHello` 里的 Vignette 标志）。
- 改了任何带输入框的页面，都要想一遍「键盘弹起 / 收回时这里会怎样」。

### 同一功能只做一套界面、一个入口
- **问题**：助理设置里选模型是一长串平铺，和聊天里那套按供应商分页的不一样；世界书在输入框旁和「＋」菜单里各有一个入口。
- **规矩**：
  - 选模型全 App 只用 `ModelPicker.kt` 的 `ModelPages`。场景差异靠参数：`sel` 定哪个打勾（null 表示跟随全局），`header` 加第一页顶上一行，`onAdd` 加「添加供应商」。
  - 加按钮、加入口前，先在代码里搜有没有现成的。世界书入口只在「＋」菜单（`ChatTools.kt`）。

### 名单不要写死
- 供应商 = `BUILTIN_PROVIDERS` + `CUSTOM_PROVIDERS`，`PROVIDERS` 是两者合起来的 getter。用户自建的存在 `assistant-config` 的 `custom` 里，用 `store.addProvider(...)` 添加、`store.removeProvider(id)` 删除。删除时会把用到它的全局模型和助理默认模型一起退回（`AssistantExt.dropProvider`）。
- 以后有类似的名单（语音服务、搜索源等）也照这个做：内置加自建，删除时清理所有引用。

### 拖动排序
- 用 `sh.calvin.reorderable:reorderable:3.1.0`，不要手写。
  - `LazyColumn`：`rememberReorderableLazyListState(listState) { from, to -> … }`、`ReorderableItem(state, key) { dragging -> }`，把手用 `Modifier.draggableHandle()` 或 `longPressDraggableHandle()`。
  - 普通 `Column`：`ReorderableColumn(list, onSettle = { from, to -> }, onMove = { 震动 }) { i, item, dragging -> key(item.id) { ReorderableItem { … } } }`。
- 例子：`WorldBookUi.kt`，长按书名拖书，拖条目左边的把手排条目。

### 编译坑
- **问题**：`ColumnScope.AnimatedVisibility … cannot be called in this context with an implicit receiver`。
  - **原因**：在 `ColumnScope.xxx()` 函数里的 `Box` 中写了 `AnimatedVisibility`。
  - **改法**：拆成独立的 `@Composable` 函数（例：`WorldBookUi.kt` 的 `WbToast`）。
- `HapticFeedbackType` 可以用 `SegmentFrequentTick`、`GestureThresholdActivate`、`LongPress`、`TextHandleMove`（Compose 1.12）。
- 新加依赖前先确认版本存在、兼容 Kotlin 2.3、compileSdk 37、minSdk 29。仓库在 mavenCentral。

### 用量页（第 536 版起）
- 结构只有两张卡：当前渠道余额卡 + Token 统计卡。不要再加「当前会话」「每周限额」「所有模型」这类卡，用户明确说冗余。
- 余额卡跟着当前模型的渠道走；点头部弹层看各家余额，手动选了别家，换模型时回到当前渠道。
- 满格 = 最近一次充值后的余额（余额比上次多就算充值），存在 `usage-topup-v1`；OpenRouter 用 `/api/v1/credits` 的总额。
- 花费只按 `ModelUsage.PRICES` 里核实过的官方价算；没单价的模型只显示 Token，不要猜价。
- DeepSeek 充值（`DeepSeekPay.kt`）：官方没有公开下单接口，连官方客户端 DeepSeek Harness 也是内嵌 `/top_up`。做法是在 1dp 高、全透明的已登录 WebView 里自动填金额、选付款方式、点提交，拦截 `weixin://`、`alipays://`、`intent://` 拉起付款 App；15 秒没拉起就展开页面手动完成。登录页里的「微信授权登录」也会跳 `weixin://`，那时不能当成付款关弹层。
- 页面结构变了导致自动填写失败时，先让用户截充值页的图，再改 `DeepSeekPay.script()` 的匹配规则。

## 四、网页原型

- 图表配色先跑 dataviz 的 `validate_palette.js`（深色底 `#2b3038`）：统计卡的输入 / 缓存 / 输出用 `#3FA35E` / `#6F83EA` / `#CF763A`，已通过。

- **键盘**：viewport 加 `interactive-widget=resizes-content`；iOS 用 `visualViewport` 算键盘高度，把弹层抬起来，收起后 `scrollTo(0,0)`；输入框字号至少 16px，否则 iOS 聚焦时会放大页面、不再缩回。
- **问题**：用 JS 设高度的块高度为 0。
  - **原因**：父元素高度随内容（auto），子元素写了 `flex:1`，flex-basis 0 盖掉了设的 `height`。
  - **改法**：这类块写 `flex:none`。
- **弹层**：遮罩铺满整屏、弹层贴边、可下拖关闭，进 420ms `decel`、出 280ms `accel`（dongxiaosheji `amor-bottom-sheet`）。
- **发布前**用 Playwright 截图自查一遍（`python3` 已装 playwright），发布时用 `publish_files`。
- 需要对比方案时，在原型里放一个切换开关（例：聊天模型原型的 A / B）。

## 五、发安装包

- `check` 分支编译只出 artifact，不出 Release。直链这样发：
  1. 编号 = 526 + 那次 "Android APK" run 的 `run_number`（例：run 9 → 第 535 版）。
  2. 查 artifact：`gh api repos/dhhd1426-ops/Amor/actions/runs/<run id>/artifacts`，记下 `id` 和 `digest`（sha256）。
  3. 从编译通过的那个提交开分支 `release/check-apk-<编号>`，加 `.github/workflows/publish-check-apk-<编号>.yml`（照 `release/check-apk-535` 分支里那份改编号、artifact id、sha256、目标提交、说明）。推上去，它会下载 artifact、核对 sha256、`gh release create app-build-<编号>`。
  4. 直链：`https://github.com/dhhd1426-ops/Amor/releases/download/app-build-<编号>/fuguang-lueying-<编号>.apk`
- 这边下载不了 artifact（blob 地址被拦），所以校验用 API 返回的 `digest`。
- `gh` 不能用 GraphQL（`gh release list` 之类会 403），一律用 `gh api repos/...`。
- 编译失败：用 `gh api repos/dhhd1426-ops/Amor/check-runs/<job id>/annotations` 读错误行。
